# 演示话术与 LLM 输出预跑

这份话术用于三分钟现场演示。示范节点固定为“大语言模型的能力与边界”。

当前仓库没有配置 LLM Key。下面两组回答和评估结果已经固化在 src/agent/demoFixtures.ts。现场断网或未配置 Key 时，仍能稳定演示发现缺口、补学和节点变绿的完整过程。输入其他内容时，系统继续使用原有通用兜底，不会误判为演示结果。

## 第一次回答

展示者粘贴下面这句话。

> 大语言模型会根据学过的大量文字预测接下来最可能出现的内容，所以很擅长总结、改写和对话。

刘看山应判定为“待巩固”。用户已经理解生成机制和擅长任务，但没有说出事实错误风险，也没有给出产品对策。

    {
      "mastery": "partial",
      "understood_points": [
        "知道模型会根据文本规律生成内容",
        "说出了总结、改写和对话等擅长任务"
      ],
      "missing_points": [
        "还没有说明模型可能把错误内容说得很像真的",
        "请再补一个产品如何处理事实错误的例子"
      ],
      "next_action": "practice"
    }

现场口播

> 我故意漏掉了“模型会把错话说得很像真的”。刘看山抓到了这个缺口，所以没有让我过关。

## 第二次回答

展示者补充并粘贴下面这句话。

> 大语言模型本质上根据文本规律预测下一个词，擅长总结、改写和对话。但它可能把错误内容说得很像真的，也不擅长精确计算。做产品时要增加检索、来源引用或人工确认，不能直接把回答当事实。

刘看山应判定为“已掌握”。系统随后把当前知识节点变为绿色，并允许用户继续前进。

    {
      "mastery": "mastered",
      "understood_points": [
        "理解了模型通过文本规律进行预测",
        "说清了模型的擅长任务和事实错误风险",
        "给出了检索、引用来源和人工确认等产品对策"
      ],
      "missing_points": [],
      "next_action": "advance"
    }

现场口播

> 我补上了模型的风险和产品处理办法。这次刘看山确认我真的理解了，知识节点也随之变绿。

## 演示顺序

1. 打开“大语言模型的能力与边界”知识卡。
2. 用第一次回答展示“待巩固”和具体缺口。
3. 按照提示补学，再提交第二次回答。
4. 确认结果变为“已掌握”，知识节点变绿。

## 验收清单

- 未配置 LLM Key 时，两次固定回答能得到上面的固定结果。
- 第一次回答不会让节点直接通过。
- 第二次回答会返回 advance，并推动节点变绿。
- 输入任意其他内容时不会命中演示样例。
- 页面刷新后仍可重新复现演示。

这次验收覆盖离线固化输出。接入真实 LLM Key 后，还需要使用同一组输入补做外部模型预跑。对外演示时应如实说明当前使用的是离线保障方案。
